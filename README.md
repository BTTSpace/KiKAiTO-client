# KiKAiTO English website revamp

Start with [change batch CR-2026-10-12-02](https://github.com/BTTSpace/KiKAiTO-client/issues/19) for the current delivery descriptions. [Customer decisions](https://github.com/BTTSpace/KiKAiTO-client/issues/3) lists only questions requiring an answer. For earlier feedback, use the [request feedback register](docs/customer-feedback/README.md) and [previous batch](https://github.com/BTTSpace/KiKAiTO-client/issues/18). Each record preserves the original document, its revisions and links to affected issues.

- [How to read and reply](https://github.com/BTTSpace/KiKAiTO-client/issues/1)
- [All features and progress](https://github.com/BTTSpace/KiKAiTO-client/issues/2)
- [Decisions awaiting confirmation](https://github.com/BTTSpace/KiKAiTO-client/issues/3)
- [Communication rules and checks](docs/communication-rules.md)
- [Request feedback register](docs/customer-feedback/README.md)
- [v2 baseline scope](docs/scope-v2.md)

The existing system is bilingual; this work revamps the English version and preserves Chinese behavior. Every issue shows complete English with expandable Chinese below. Qualified screenshots must match the original website design; missing evidence remains pending.

Reply in either language on the relevant feature issue. Without a GitHub account, use your usual contact channel and provide the feature name or link; the owner records the respondent, date and reply. This repository is public, so private materials use the usual private channel.

Permanent source and batch labels support historical lookup. `updated-review` marks content to read, while `請客戶確認` marks an unanswered customer choice. `bilingual` identifies language availability, and `scope-change` identifies scope added to the original baseline. Customer silence is not approval. The owner records demonstrated version/date, check results and customer confirmation before closing feature issues.

Source code and detailed check logs remain private. Repository visibility is a separate decision.
